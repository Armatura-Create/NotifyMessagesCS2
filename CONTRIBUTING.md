# Contributing

## Сообщение коммита — это текст релиза

`CHANGELOG.md` в репозитории нет. Описание GitHub-релиза собирается из коммитов между
предыдущим тегом и новым, поэтому **заголовок коммита читает пользователь плагина**.
Заголовок, который нельзя прочитать, становится строкой релиза, которую нельзя прочитать.

Формат — [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<scope>)!: <заголовок>

<тело>
```

| Часть | Правило |
|---|---|
| `type` | один из таблицы ниже — определяет раздел в описании релиза |
| `scope` | необязателен; цель, которую трогает коммит: `cssharp`, `swiftly`, `ci`, `docs` |
| `!` | добавляется к типу, если изменение ломает совместимость — уходит в отдельный раздел наверху |
| заголовок | повелительное наклонение, без точки в конце |

| Тип | Раздел релиза | Для чего |
|---|---|---|
| `feat` | Added | новое поведение, которое заметит владелец сервера |
| `fix` | Fixed | дефект, достижимый в выпущенной сборке |
| `perf` | Performance | то же поведение, дешевле |
| `refactor` | Changed | внутренняя перестройка без изменения поведения |
| `docs` | Documentation | README, комментарии |
| `build` | Build | сборка, зависимости, упаковка |
| `ci` | CI | workflows |
| `test` | Tests | только тесты |
| `chore` | Chores | всё остальное без видимого эффекта |

Коммит не по форме **не теряется** — он попадает в раздел «Other». Молча выбросить
изменение из описания хуже, чем показать его без категории, но «Other» — признак того,
что заголовок стоит поправить.

Тело коммита — для того, кто через два года откроет `git blame`: *почему* так, какая была
альтернатива, что сломается, если это откатить.

## Два таргета — один конфиг

`cssharp/` и `swiftly/` — две независимые реализации с одинаковой раскладкой файлов.
Код продублирован сознательно: цели развиваются независимо и не тянут друг друга.
Общее между ними — **формат конфигов**: `Settings.json`, `Messages.json`, `Ads.json`,
`Servers.json` переносятся между платформами без правок. Меняешь формат — меняй в обеих
целях, или ни в одной.

## Перед пушем

```bash
export PATH="$HOME/.dotnet:$PATH"

dotnet test cssharp/NotifyMessages.sln
dotnet test swiftly/NotifyMessages.sln
```

Тесты Swiftly-цели, которым нужна сборка `SwiftlyS2.CS2.dll`, выполняются только в
x64-процессе (эта сборка собрана только под x64 — выделенный сервер CS2 другим не бывает).
На arm64-машине они пропускаются с внятной причиной, в CI выполняются все.
